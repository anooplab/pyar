# R3 scientific regression and backend validation

Status: implementation is complete on the R3 review branch. Exact-head CI and
scientific-owner review remain required. This work changes tests, validation
tools, CI and documentation only; it does not change scientific algorithms or
public runtime APIs.

## Framework delivered

- Added `tier1`, `tier2`, and `tier3` pytest markers and marked deterministic
  analytical/structural invariants for AFIR and soft-min energy/force behavior,
  collective-coordinate gradients, bias-controller invariants, molecular XYZ
  geometry, and coordinate-graph structure.
- Added a dedicated Tier 1 command to required PR quality CI. Existing unit,
  regression, integration, optional-dependency, and full-suite coverage remain
  active. Benchmark harness tests and mocked backends are not called real
  scientific calculations.
- Added weekly and manual `.github/workflows/scientific-tier2.yml` execution of
  the existing real xTB GFN2 constrained-scan harness. It records the candidate
  SHA, PyAR/xTB versions, structured summary, and scan artifacts; the workflow
  uses no proprietary program.
- Added `tools/scientific_validation.py`, which checks immutable input and
  reference hashes, required metadata, exact charge/multiplicity/method/backend,
  backend version, finite metric values, declared units/tolerances, raw log
  references, and explicit authorized exceptions. Missing mandatory cases
  become `NOT_TESTED`; unauthorized exclusions become `BLOCKED`. It writes
  machine-readable JSON and a human-readable Markdown report and exits nonzero
  on an incomplete or failing evidence set.
- Added a machine-readable benchmark catalogue and backend matrix tied by test
  to `BACKEND_CAPABILITIES`. Added architecture, tolerance, provenance,
  backend, catalogue, and troubleshooting documentation under
  `docs/scientific_validation/`.
- Updated the canonical G2 release gate and preparation instructions to use the
  scientific comparator while retaining missing corpus/approval as blockers.

## Follow-up: optimization safety remediation

PR #76 removes those 17 strict expected-failure entries only after converting
each instance into an ordinary regression test, and adds fixes for the
corresponding optimization, cache, geometry-validation, and failure-recovery
paths. See `r3_safety_remediation.md` for the test-to-fix mapping. This is
software-safety evidence; it does not add independently approved reference
chemistry or close real-backend workflow gaps. The original counts and results
above describe the earlier R3 validation revision. Rebased exact-head CI and
review results for PR #76 must be considered separately before integration.

The external dataset RGD1 does not establish redistribution permission, so no
source structures were copied into a new public reference folder. Existing
microsolvation and clustering pilots remain bounded studies and are not
automatically promoted to release benchmarks. Tier 2 workflow execution on
GitHub Actions and the full exact-head CI results remain to be reviewed after
push.
