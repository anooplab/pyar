# R1 engineering gates and execution record

R1 implements CI and packaging foundations only. R2–R5 and publication remain
outside this change. The Python 3.10–3.13 test matrix and Python 3.10/3.13
installation matrix follow the existing supported classifiers. Public CI uses
Ubuntu and open-source dependencies; it requires no proprietary calculators.

## Required checks

The existing CI workflow retains full tests, strict documentation, optional Sella
and geodesic jobs, wheel/sdist installation and all nine extra installation modes.
Installation modes now consume the same uploaded wheel, rather than rebuilding
from source. The archive job runs Twine, metadata/content/license checks and clean
wheel/sdist installs. Console executable registration, help, import version and
missing-extra/executable diagnostics are checked outside the checkout.

`R1 required checks` depends on every CI job, runs even after a failed dependency,
and rejects failed/cancelled/skipped jobs. It produces candidate SHA/version,
required-job results and exact wheel/sdist SHA-256 evidence. Configure this stable
check as required in repository rules through an authorized administrator; this
change does not modify remote branch protection. The evidence script consumes
trusted same-run GitHub `needs` results; it is not an independent remote CI
attestation verifier or a publication authorization mechanism. R5 must consume
verified same-candidate results and approved bytes rather than trusting arbitrary
user-authored JSON or rebuilding independently.

JUnit reports retain warnings, skipped cases and strict xfails. The omission
checker rejects new xfail identities/reasons and skips outside the reviewed
optional-test module inventory. Optional dependencies differ between jobs;
`tests/optional_test_modules.json` records the existing locations where optional
availability can skip cases. This inventory is an explicit exclusion, not a
scientific validation claim. Existing 17 strict recovery audit xfails remain
known defects and potential release blockers under G1/G2; R1 does not repair or
approve their scientific behavior. Their exact identities/reasons are recorded
in `tests/expected_xfails.json`. Unexpected passes still fail via strict xfail.

## Test and quality policy

Run the full suite with `python -m pytest --cov=pyar --cov-report=term-missing`.
Run the fast lane with `python -m pytest -m '(unit or regression) and not slow
and not external_backend'`. Strict marker/config validation rejects typos.

- `unit`: explicit isolated-logic inventory in `tests/conftest.py`.
- `regression`: reviewed defect/compatibility tests, overlaid on unit/integration.
- `integration`: conservative default for existing composed/mocked workflows.
- `scientific`: explicitly marked comparisons to approved numerical references.
- `external_backend`: explicitly requires an actual external chemistry program.
- `slow`: expensive tests, omitted from the fast lane only.

New tests should declare their intended markers. No existing test is omitted
from the full suite because of categories. No scientific campaign is registered
by R1; benchmark-harness tests and synthetic/mocked optimizers remain engineering
tests. Existing real missing-executable tests validate diagnostics, not chemistry.

Install the `quality` dependency group to use pinned Ruff 0.14.1.
`python -m ruff check tests tools` enforces fatal/error-prone rules on the test
and engineering surface. Format checks cover the new gate tools, conftest and
release-evidence tests. Legacy scientific source formatting/lint cleanup is
explicitly excluded to avoid a broad unrelated rewrite. A whole-source diagnostic
`python -m ruff check pyar tests tools` found two pre-existing F821 defects:
`pyar/backends/ASE.py:88` uses undefined `pythonpackage` and
`pyar/backends/turbomole.py:136` uses undefined `gamma`. Scientific-owner approval
is needed for a separate behavior fix; neither is silently repaired here.

`python -m sphinx -E -b html -W --keep-going docs OUTPUT` remains mandatory CI;
comprehensive documentation reconciliation belongs to R2. Sphinx regenerates
`docs/generated_api.rst`; review/restore only generated changes from the build.

## Execution evidence

Local evidence is retained outside the checkout in a temporary evidence directory;
CI uploads named distributions, per-Python JUnit reports, fast regressions and
candidate evidence. No old release artifacts qualify a new candidate. Build tools
and dependencies resolve at execution time; the reports do not claim hermetic
reproducibility. Linux is the current CI platform; Windows/macOS and licensed
backend/model calculations remain unvalidated. Alias/composite extras not in the
installation matrix have metadata coverage, not exhaustive runtime coverage.

The final execution results and CI run are recorded below after validation.

Executed local checks (2026-10-18):

- Full suite before gate-tool additions: 1,683 passed, 17 strict xfails, 75.49%
  coverage; gate-tool tests subsequently executed separately (11 passed).
- Fast lane: 228 passed, 17 strict xfails, 1,463 deselected before the final three
  omission-gate tests were added. Deselection is confined to this additional
  fast lane; the full suite remains required.
- Strict Sphinx command above: passed, including warning-as-error handling.
- `python -m build --outdir DIST`, `python tools/check_distributions.py DIST`
  and `python -m twine check DIST/*`: passed after adding wheel license notices.
- Two fresh Python 3.11 environments, normal wheel and sdist installs,
  `python -m pip check` and outside-checkout `installation_smoke.py core`:
  passed. These cover actual dependency resolution, help and actionable absent
  optional dependencies. Public CI additionally exercises extra/backend-negative
  contracts in the installation matrix.
- Ruff check and scoped format check: passed. Candidate evidence negative tests
  reject stale SHA/version, omitted/failed checks, tampered hashes and old wheels.

The first CI attempt exposed three engineering defects: the new fast lane needed
Open Babel like the full lane; class-based JUnit identities needed proper module
parsing; and CLI smoke checks needed the tested interpreter's script directory,
rather than the calling shell's PATH. These were fixed without changing test
assertions, scientific algorithms or optional dependency requirements. Failed
attempt logs are retained in the local evidence directory and GitHub Actions.

Final candidate CI status must be read from the branch's exact head run and the
`R1 required checks` artifact. This static execution history does not grant a
release verdict. Publishing workflow and Pages workflow are unchanged; publishing
itself is deliberately NOT TESTED. Remaining release blockers include scientific
corpus/tolerances, known strict xfails, approval protections and exact-byte
promotion; those belong to the separately authorized later stages.
