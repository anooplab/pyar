## Findings that determine the design

1. **Layout v1 is not state schema 1.** Reaction state already uses version 2;
   conformer state uses schema 3. A separate `layout.json` marker is necessary.
2. **Backend paths are execution contracts.** `optimiser.optimise` reuses
   `job_<name>/result_<name>.xyz`; growth checks both job and result names, and
   aggregate finalization searches `ag_*/.../selected/result_*.xyz`. Moving
   these independently would bypass reuse or change candidate discovery.
3. **Reports can currently be scientific dependencies.** NEB hashes the bytes
   of upstream `<stage>_summary.json`; reaction characterization hashes the
   discovery `reaction/state.json`, trace and candidate metadata. Existing
   files must remain untouched by the layout project. New v2 stages need
   immutable completion records before reports can be freely rebuilt.
4. **Resume is workflow-specific.** Grow returns a completed result, but
   regenerates its `final/` snapshot/report; microsolvation returns completed
   state directly. Aggregate and legacy solvation reject completed resume.
   Reaction has a separate completed-discovery reader for characterization.
   Conformer refuses an existing state and has no generic resume.
5. **A universal jobs/backend split cannot safely be introduced now.** Grow's
   addition service uses trial files and selected refinements in its cwd;
   microsolvation runs optimizer jobs inside `candidates/`. Retain a bounded
   `execution/` namespace for these native trees, and index their artifact
   roles explicitly. This is a proposed amendment requiring architecture review.
6. **Present atomic writes are not a complete crash protocol.** Grow fsyncs
   a temporary JSON file before replace, but does not fsync its directory;
   other owners have different write behavior. Snapshot publication can precede
   state publication. None of these owners provides a shared single-writer guard.
   PR 0 does not repair or reinterpret existing v1 crash behavior.

## Known gaps and required acceptance checks

- No real ORCA/xTB/AIMNet2 calculation or minimal installation without optional
  dependencies was run in PR 0. Universal layout tests must be dependency-free;
  optional-provider smoke tests remain opt-in implementation/release checks.
- No single existing fixture runs real reaction discovery and the entire
  validated pathway chain together. The matrix separates discovery, bridge and
  stage-engine evidence; PR 6 must supply integrated mocked and opt-in real runs.
- Existing snapshots are captured before implementation; synthetic failure
  states and native scratch coverage remain bounded by the selected fixtures.
- Required v2 tests: interruption at each publish/commit boundary, duplicate
  invocation, explicit stale-lock recovery, unknown/corrupt markers, checksum
  mismatch, symlink/path traversal rejection, missing inputs, immutable request
  mismatch, report regeneration without invalidating completed dependencies,
  read-only preflight, result API/inspect and benchmark dispatch.
- Compare geometry, physical energy (or absent energy), survivor identities,
  rank, site restrictions, coverage, connectivity and gates against these
  baselines. No test in PR 0 can prove equivalence of code not yet implemented.
